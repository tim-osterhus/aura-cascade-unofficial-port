### Native Runtime Controls

An independent Astra QA lane reviewed the loader changes and authored the
test-only command fixture; the integrator compiled and executed it against the
packaged server. The initial three controls and evidence were independently
reviewed; final five-control and visual evidence received a separate review.

1. Damage: real entity hits of 6 then 10 preserve a NeoForge invulnerability
   reduction modifier. Ordinary and modified controls finish at 10 and 4 health.
2. Red Hole lifetime: real item ticks preserve a 100-tick `ItemExpireEvent`
   extension through an NBT round trip and eventually expire; ordinary items
   retain their normal lifetime. Accelerated ages are not an elapsed-time test.
3. Thief drops: real villager deaths with a controlled winning random roll
   produce one copied reward; canceling `LivingDropsEvent` spawns no reward.
4. Enchantment bonus drops: real golem deaths compare unenchanted/enchanted
   controls and cancellation; bonuses stay within NeoForge's drop capture.
5. Harvesting: actual `ServerPlayerGameMode.destroyBlock` calls remove connected
   oak only with Green, while diagonal birch remains. The unenchanted control
   retains both neighboring logs. This does not cover every harvesting mode.

All five passed on the reviewed candidate. The fixture supplies entities,
equipment and RNG preconditions; production methods produce the outcomes.
It is packaged separately and is not a release dependency.

## Loader Mapping And Review Corrections

| Fabric boundary | Native implementation / ordering |
| --- | --- |
| Main/client initializers | `@Mod`, registry events, enqueued common/client setup; client classes guarded by physical side |
| Direct content registration | Existing catalog in registry phases; block items deferred until item phase; native entity/block-entity builders |
| Persistent player attachment | Deferred NeoForge attachment, same codec/slot constraints, copy-on-death; owner-only packets on mutations/login/respawn/dimension change |
| Accessory death inventory | `LivingDropsEvent` collection; keep-inventory gate retained |
| Menu and action payloads | Native payload registration/main-thread handlers; server menu, distance, alive/spectator and equipment checks retained |
| World/server ticking | `LevelTickEvent.Post` (server levels) and `ServerTickEvent.Post` |
| Player interactions | NeoForge interaction events with explicit cancellation/result; Fairy lifecycle uses native player/entity/server events |
| Successful block break | `destroyBlock` wrapper captures pre-break state/entity in locals, invokes canonical after-break only on success |
| Damage modifier mixin | Read/write NeoForge's current damage container, not the stale vanilla argument |
| Item expiry mixin | Preserve the larger current lifespan before native expiry handling; do not overwrite event extensions |
| Bonus loot mixin | Inject before the second `captureDrops` call, while capture is active and before cancelable drop processing |
| Client UI/render hooks | Native HUD/screen/key/menu/renderer events; client-only creative screen accessor |
| Energy lookup | Native sided `IEnergyStorage` capability; retained formula/flood limit and actual accepted-energy accounting |
| Fabric custom-data ingredients | Registered `aura:custom_data` subset matcher; exact native component matching for potion requirements |

Independent review caught and corrected the damage-container, expiry-extension,

regressions before this checkpoint. The obsolete enchanter bootstrap remains

## Harness Corrections

- Native JUnit bootstraps NeoForge rather than Fabric Knot/reflection. ModDevGradle
  overrides test cwd after evaluation, so resource audits restore the repo root
  after that override. Vanilla tag audits read the separate Minecraft resources
  JAR. Assertions were retained, not skipped.
- QA classes have a separate package from production classes to avoid Java
  module split-package failures. Only the standalone helper task packages them.
- Windows launcher validation found and fixed a case-insensitive PowerShell
  variable collision, condition grouping, checksum response decoding, modern
  LWJGL native artifact extraction, and the vanilla JAR ignore-list name.
- First flat-world creation used default settings and logged a missing `layers`
  warning; the isolated server settings now explicitly specify layers/biome.
- Independent visual review caught a nonblocking invalid client simulation
  distance of 4. The final fresh-world rerun uses the valid minimum of 5, exits
  normally, and has no ERROR entries in its game log. Earlier evidence is retained.
- Launches use isolated directories and an offline local QA identity, with no
  external account credentials. Dedicated server binds only to loopback.

## Reproduction

Run Java 21 and `./gradlew --console=plain test build qaObserverJar`.
For bounded runs use `scripts/qa/measure-gradle.ps1` with `-JavaHome` and a fresh
`-Label`. Install a disposable client/server with
`scripts/qa/neoforge/install-packaged-neoforge.ps1`; it previews unless `-Execute`
is supplied. Stage the optional observer only for QA.

The dedicated-server monitor is
`scripts/qa/neoforge/measure-packaged-server.ps1`. Pass `-Commands aura_qa_hooks`
and a completion log pattern, then verify `hooks-result.json.success` as well
as process readiness and exit status. A normally stopped server is not by
itself a passing gameplay fixture. A previously accepted EULA is required.

The client helper supports `-GenerateLaunchOnly`, `-Execute`,
`-QuickPlaySingleplayer`, a fresh `-ObserverDirectory`, and `-ObserverScene`.
Quick-play requires a disposable world already in the profile's `saves` folder.
Observer scene setup modifies that world; never point it at a personal world.
