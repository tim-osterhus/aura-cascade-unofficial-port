# Current Implementation Usability Audit

Date: 2026-09-22

Scope: source/test audit of Encyclopedia Aura, aura feedback, machine and recipe progression, storage books/shelves, fairies, accessory controls, and external-energy export.
Baseline read: parent `AGENTS.md`, `README.md`, and `PORTING_NOTES.md`.

## Evidence Boundary

- **Confirmed** means directly visible in the checked-out source/tests or in the inspected live-client log. This audit uses the existing dirty worktree as-is and makes no claims about uninspected versions.
- **Runtime hypothesis** means a consequence that still needs gameplay observation. No Gradle, Java, Minecraft client, or server was launched by this audit; reproduction steps below are proposed checks, not a claim that each issue was live-reproduced.
- Historical expectations below come from this repo's `PORTING_NOTES.md` descriptions of `AuraCascade-592.jar`; this audit did not repeat the separate original/public-source research.

## Findings

1. **[P1] Long Encyclopedia pages are not fitted to the vanilla book viewport.** **Source fact:** `EncyclopediaAuraContent` appends each section as one full page (`src/main/java/pixlepix/auracascade/lexicon/EncyclopediaAuraContent.java:25, 58, 66, 74, 81`); `page()` passes the entire string through as one literal component (`.../EncyclopediaAuraContent.java:168, 169`). The Fairy, enchantment, matrix, and late-systems sections are especially dense. The current test checks phrase presence, not rendered line count or page geometry (`src/test/java/pixlepix/auracascade/lexicon/EncyclopediaAuraContentTest.java:14, 20`). **Runtime hypothesis, corroborated by the player report:** text beyond the vanilla book's visible area is clipped rather than continued. **Reproduce:** open Encyclopedia Aura and inspect the Fairy and Enchant Matrix pages at ordinary GUI scale, including their last lines. **Expected vs actual:** all guide text readable across deliberate page breaks; source currently has no pagination or fitting step, and clipping is reported but not independently screen-verified here. **Accept when:** a client screenshot confirms every page's last line is visible at supported GUI scales and any overflow continues onto a page.

2. **[P1] Machine progression recipes and operating steps are not discoverable in-game.** **Source fact:** the guide gives only a broad consumer/vortex summary (`.../EncyclopediaAuraContent.java:41, 42, 43, 44`); custom world and vortex recipes are loaded from fixed classpath resource lists (`src/main/java/pixlepix/auracascade/data/recipe/AuraWorldRecipeCatalog.java:18, 49`; `.../AuraVortexRecipeCatalog.java:20, 34, 48`), not presented in the guide. Consumer processing scans nearby dropped item entities (`src/main/java/pixlepix/auracascade/block/entity/AuraConsumerBlockEntity.java:156, 169, 469`), a key interaction detail absent from that guide text. The legacy guidebook evidence lists consumer/progression topics and many entries (`PORTING_NOTES.md:79, 91, 92`). **Reproduce:** obtain an ore processor or a vortex recipe output, then try to learn its accepted inputs, setup, and aura requirements using only the mod's in-game interfaces. **Expected vs actual:** the documented legacy topic breadth should give players a discoverable route through machine progression; current text names machine families but supplies no recipe index or concrete operating instructions. **Accept when:** every custom machine/vortex recipe and its inputs, placement/setup rules, and required aura are accessible in-game or linked from a navigable guide section.

3. **[P2] Encyclopedia Aura is a linear ten-page summary with no clickable navigation.** **Source fact:** exactly ten section pages are constructed as plain text, and no page component carries a click event (`.../EncyclopediaAuraContent.java:25, 26, 31, 36, 41, 46, 53, 58, 66, 74, 81, 169`). The recorded legacy guidebook had nine categories and 101 entry keys / 261 page keys (`PORTING_NOTES.md:79, 80, 81, 82, 91`). **Reproduce:** open the book and try to jump from its opening page to Storage, Fairies, or a named enchantment. **Expected vs actual:** category/topic navigation should retain the legacy guide's discoverability; actual access is sequential page turning through ten summaries, with no contents links or topic anchors. **Accept when:** a contents page links to sections and section pages provide a clear return path, with navigation tested from the actual book screen.

4. **[P2] The onboarding checklist marks possession as task completion.** **Source fact:** `onboarding()` checks whether named items are in the player's inventory (`.../EncyclopediaAuraContent.java:101, 102, 103, 104, 105, 106, 107, 108`), but the checklist labels those booleans “Place an Aura Node,” “Run an Aura Pump,” and “Power a consumer” (`.../EncyclopediaAuraContent.java:122, 123, 124, 125, 126`). **Reproduce:** keep a pump or consumer item in inventory without placing or powering it, then use the guidebook. **Expected vs actual:** a completed-action checklist should reflect completed actions, or the text should say it tracks acquisition; current `[x]` can claim operational milestones that never happened. **Accept when:** progress is event-backed, or checklist wording and completion marks accurately describe item ownership.

5. **[P2, scope decision pending legacy evidence] The aura Monitor exposes comparator strength, not a player-readable aura display.** **Source fact:** the Monitor implements analog and redstone output (`src/main/java/pixlepix/auracascade/block/AuraMonitorBlock.java:35, 41, 45, 51`), gathers adjacent network signals, and returns their strongest value (`.../AuraMonitorBlock.java:55, 57, 63`; `src/main/java/pixlepix/auracascade/block/entity/AuraMonitorLogic.java:18, 20, 21, 23`). No client renderer package or live network visualization was found under `src/main/java`. **Reproduce:** place the Monitor beside nodes holding different colors/amounts; use it without a comparator, then attach a comparator. **Expected vs actual:** the guide says the Monitor “reads nearby aura strength” (`.../EncyclopediaAuraContent.java:39`); in source the actionable reading is a scalar redstone level, with no in-world color-specific quantity or flow readout. **Accept when:** original jar/source evidence establishes whether the Monitor had a player-facing readout. If it did, restore that gameplay and verify it; if not, record the comparator-only behavior as an evidence-backed scope decision. Clarifying guide text alone is not closure if the original offered more.

6. **[P2] A consumer that cannot work gives no player-facing reason.** **Source fact:** consumer block entities advance internal progress and expose an automation signal (`src/main/java/pixlepix/auracascade/block/entity/AuraConsumerBlockEntity.java:75, 87, 107, 114`); the block offers signal output, with no interaction/status method (`src/main/java/pixlepix/auracascade/block/AuraConsumerBlock.java:67`). Input/target checks can return false when no valid item or world target is nearby (`.../AuraConsumerBlockEntity.java:156, 169`). **Reproduce:** place a processor without aura, then with aura but only an unsupported dropped item; observe it without redstone instrumentation. **Expected vs actual:** the player should be told whether input, power, target, or recipe is missing; actual operation can remain idle with no on-screen diagnostic. **Accept when:** a simple inspect/use action or visual state distinguishes at least waiting-for-input, waiting-for-power, working, and blocked/no-valid-target.

7. **[P2] Storage books hide which items are stored and only extract the first stored type.** **Source fact:** the book tooltip reports capacity and aggregate counts (`src/main/java/pixlepix/auracascade/item/books/StorageBookItem.java:66`; `src/main/java/pixlepix/auracascade/item/books/StorageBookData.java:93, 101, 115, 116`). Extraction returns the first entry in stored order (`.../StorageBookData.java:93, 94, 95, 110`); shelf inspection also reports only type/item totals, and sneak-use invokes that extraction (`src/main/java/pixlepix/auracascade/block/StorageBookshelfBlock.java:86, 94, 106, 107`). **Reproduce:** store two item types in a book/shelf, inspect the tooltip and shelf, then sneak-use to retrieve. **Expected vs actual:** players should be able to identify and retrieve the desired stored item; actual UI reveals totals only and withdraws a stack without choosing a type. **Accept when:** contents are inspectable and retrieval can target a selected type while preserving item components and remaining counts.

8. **[P2] Fairy roles can be cycled, but their functions are not explained in the guide.** **Source fact:** the guide's Fairy page lists role names but no effects (`.../EncyclopediaAuraContent.java:58, 59, 60, 62, 63`); the charm tooltip only says sneak-use cycles roles (`src/main/java/pixlepix/auracascade/item/FairyCharmItem.java:44, 51, 52`). Legacy lexicon evidence enumerates role-specific entries (`PORTING_NOTES.md:98, 99`). **Reproduce:** sneak-use a charm through roles, read its tooltip, bind it to a ring, and consult Encyclopedia Aura for what the selected fairy does. **Expected vs actual:** the guide should help select among the recovered roles; actual role names and selection control are visible, but behavior/triggers are not. **Accept when:** each role has a concise in-game description of effect, trigger/range, and any material risk before binding.

9. **[P2 UX opportunity; legacy regression unconfirmed] There is no persistent accessory-equipped tooltip or slot UI in the port-owned item code.** **Source fact:** the inventory-backed bridge locates equipped accessories by custom item data (`src/main/java/pixlepix/auracascade/compat/InventoryAuraAccessoryBridge.java:12, 14, 18`; `src/main/java/pixlepix/auracascade/compat/AuraAccessoryState.java:16, 17, 19`). `AuraAccessoryItem` has no `appendHoverText`; `RingOfShatteredStoneItem` adds an effect tooltip, not equip state (`src/main/java/pixlepix/auracascade/item/AuraAccessoryItem.java:6`; `.../RingOfShatteredStoneItem.java:48, 55`). Passive accessories equip on use and unequip on sneak-use, with a one-shot status message (`src/main/java/pixlepix/auracascade/item/AuraItems.java:744, 750, 751, 755, 756`). The intentional Baubles replacement is documented (`PORTING_NOTES.md:194`), but this audit has no original UI evidence establishing a lost equipped-state tooltip. **Reproduce:** equip an amulet, open inventory, and check whether its tooltip persistently identifies it as equipped; also verify use/sneak-use and the confirmation messages. **Expected vs actual:** the current flow does provide a one-shot state-change message; a persistent inventory indicator would be useful, but it is not established here as a legacy regression. **Accept when:** compare original jar/source/UI evidence. Preserve any original persistent equip-state affordance if present; otherwise treat a new tooltip/slot UI as optional modern UX, not a parity closure requirement.

10. **[P2, scope decision pending legacy evidence] Fluxing Node has an extension seam but no active external-energy adapter in this repo.** **Source fact:** the registry starts with `AuraFluxBridge.NOOP` and only changes through `install()` (`src/main/java/pixlepix/auracascade/compat/AuraFluxBridge.java:7, 8`; `src/main/java/pixlepix/auracascade/compat/AuraFluxBridgeRegistry.java:7, 8, 13, 17`). Production source calls `export()` from the Fluxing Node but no production source installs a bridge (`src/main/java/pixlepix/auracascade/block/entity/AuraNodeBlockEntity.java:55, 56`; test-only installs are in `src/test/java/pixlepix/auracascade/block/entity/AuraMonitorAndFluxLogicTest.java:35, 38`). **Reproduce:** run the mod alone, craft/place the Fluxing Node, and connect a compatible external-energy consumer; inspect whether it receives energy. **Expected vs actual:** legacy `CoFHAPI|energy` evidence motivates interoperability (`PORTING_NOTES.md:104, 157`); actual default behavior exports zero unless another integration installs an adapter. This is a confirmed no-adapter default; whether it is lost original gameplay remains to be checked against original integration evidence. **Accept when:** original jar/source evidence establishes whether the shipped original supported external-energy export. If it did, add a production adapter for the supported API and verify end-to-end transfer; if it did not, record an evidence-backed scope decision. Documentation alone is not closure if original gameplay included the integration.

## Live Client Signal

- `build/qa-audit/client/stdout.log:122, 125` records the 1.21.1 item-tag loader error for `aura:kaleidoscopic_enchantable`, caused by its reference to missing `#minecraft:enchantable/melee_weapon` (`src/main/resources/data/aura/tags/item/kaleidoscopic_enchantable.json:2-5`). All six Kaleidoscopic enchantment definitions use this custom tag for both `primary_items` and `supported_items` (for example, `src/main/resources/data/aura/enchantment/kaleidoscopic_red.json:15, 19`). **Consequence:** the live loader reports the custom tag as missing, so the intended supported-item set for these enchantments is not established in the loaded item tags; enchantment eligibility/application impact follows from those references but was not separately reproduced in-world in this audit. This is a confirmed 1.21.1 resource compatibility issue; no fix is proposed here.

## Test Blind Spots

- `EncyclopediaAuraContentTest` asserts section and phrase presence (`src/test/java/pixlepix/auracascade/lexicon/EncyclopediaAuraContentTest.java:14, 20, 32`), but does not inspect page wrapping, GUI clipping, page navigation, or click events.
- No inspected test resolves `aura:kaleidoscopic_enchantable` against Minecraft 1.21.1's actual item-tag registry; the live loader error above therefore escapes the source-level checks.
- `AuraRecipeResourceCoverageTest` validates resource JSON and registered item ids (`src/test/java/pixlepix/auracascade/data/recipe/AuraRecipeResourceCoverageTest.java:26, 37, 38`), not whether recipes/setup can be found or understood in-game.
- `StorageBookDataTest` validates capacity, filters, and first-stack extraction (`src/test/java/pixlepix/auracascade/item/books/StorageBookDataTest.java:18, 29, 35`), not storage discovery or choosing contents through a player interface.
- Flux unit coverage installs fake functions (`src/test/java/pixlepix/auracascade/block/entity/AuraMonitorAndFluxLogicTest.java:33, 35, 38`); that proves clamping/replacement, not a production integration or player-visible no-adapter state.
- No runtime screenshots or gameplay interaction evidence were collected here. The later client playtest should prioritize findings 1-6, then confirm the storage, fairy, accessory, and Flux flows end to end.
