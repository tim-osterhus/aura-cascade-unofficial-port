# Fairy Restoration Contract

## Runtime Contract

- A ring's bound role list is the source of truth. The server reconciles at most 15 `AuraFairyEntity` instances near that player in the current level; it does not scan every level or every Allay.
- Each fairy persists and synchronizes owner UUID, slot, and role. Only the server resolves owners and runs role behavior. A missing, dead, cross-dimension, or more-than-16-block-away owner causes the entity to discard itself.
- Logout cleanup removes nearby owned entities; entity-load migration removes only legacy Allays carrying both the exact `aura_fairy` tag and a parseable `aura_fairy_owner:<uuid>` tag. Untagged and incompletely tagged Allays are not candidates.
- The client renderer draws the existing `aura:textures/item/fairy_plain.png` as a half-scale camera-facing sprite and follows its 5-frame strip using the existing `.png.mcmeta` sequence. It does not register or render an Allay model.
- The recovered legacy `fairyList` indexes follow the original 0-16 order. The port's existing `boundFairies` integer array retains its old 14/15 meanings (Lighter/Glider) so already-saved modern data does not silently swap roles.

## Role Evidence Matrix

Recovered behavior below is grounded in `AuraCascade-592.jar` entity/event-handler bytecode and compared with the current port source. "Source-equivalent" means no material behavior delta was found for the listed contract; it is not a live-acceptance claim. "Adaptation" names an intentional modern API/policy substitution and is not by itself an unfinished role. "Gap" is a specific behavior not represented by the current source. "Implemented; live-unverified" means the source action/hook exists but this audit did not exercise it in a running world. "Source fix; test pending" means a correction is present in the current tree but has not yet been compiled or validated by relevant QA.

## Parent Integration

Source wiring is present: `AuraCascadeMod.onInitialize()` calls `FairySystem.bootstrapCommon()` after `AuraContent.bootstrap()`, and `AuraCascadeClient.onInitializeClient()` calls `AuraFairyClientRegistry.bootstrapClient()`. The mixin config lists the natural-spawn, mining-speed, and fall-distance fairy hooks. This establishes source registration only; Boole's packaging/runtime acceptance remains separate. No shared bootstrap, language, metadata, or item/entity registry files were changed for this audit.

## Verification Boundary

Focused tests cover role/index mapping, authorization and persistence, pure Digger/Glider multipliers, Scarer roll math, and the Extinguisher's lava-versus-fire block-state predicate. These tests do not execute fairy entity actions against a world or prove that mixins apply; the new Extinguisher regression has not been run. This remains a source/592-bytecode audit, not live acceptance. The Shooter cache source fix and unit test are pending the 198 build; the current Astra QA does not test it. Live QA remains open for role world effects, mixin/hook application, sprite trajectory, torch expiry, and the Scarer hook-scope boundary, including owner-fire and lava removal in-world. No specific Extinguisher source gap remains after the lava correction. Selector differences, Stealer's insertion guard, and Pusher's `0.4` impulse are recorded as adaptations/source-equivalent behavior rather than unfinished work. Packaging is owned by Boole.
