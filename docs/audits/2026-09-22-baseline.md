# Aura Cascade baseline audit, 2026-09-22

## Scope and evidence

This audit evaluates the current dirty working tree, not just the last commit.
The objective is a usable, faithful player experience on Minecraft 1.21.1.
Existing claims of parity and intentional substitutions are inputs to review,
not acceptance evidence by themselves. No gameplay implementation is changed by
this audit.

Working set measures resident pages; private bytes measures private committed
allocation. They are different metrics and must not be added together.
The process monitor samples once per second and stops its workload above
3800 MiB in either metric, leaving margin below 4.5 GB. This is a guard, not an
OS-enforced hard cap; brief between-sample spikes can be missed.

Scope is launched build/client processes plus the PowerShell monitor. It excludes
Windows, unrelated applications, Codex/ChatGPT desktop and agent host overhead,
and GPU VRAM. These results do not establish a 4.5 GB total-machine or total-agent
budget, and do not cover large worlds, modpacks or cold dependency setup.

A separate 03:57:28 UTC snapshot summed all ChatGPT, codex, node and Java
processes plus matching monitor/measurement shells: 3931.9 MiB working set and
4213.0 MiB private bytes (about 4.42 decimal GB private allocation). That includes
shared or unrelated agent hosts, but was only a snapshot, not continuous peak
monitoring. It is close to a 4.5 decimal GB ceiling. Do not claim that the complete
desktop-inclusive development session has been proven below that ceiling.

Raw evidence: `build/qa-audit/{baseline,client-setup,client}/` contains stdout,
stderr, memory CSV and summary JSON. Generated artifacts are evidence for this
run, not the source of truth for mod behavior.
Selected logs, CSV/JSON measurements and public-report evidence are also retained

## Client setup

The audit prepares Loom's actual dev client dependencies with `auditClientLaunch`,
then closes Gradle and launches Java directly through `measure-client.ps1`.
The client uses a 2048 MiB heap and an isolated game directory at
`build/qa-audit/client-world`; pre-existing `run/` saves are not used.

Window size was 1280 x 720, GUI scale 2, render distance 6. The initial
simulation-distance value of 4 was invalid in 1.21.1 (minimum 5); this is an audit
setup error, not an Aura bug. The attempted UI adjustment was abandoned and the
actual simulation distance was 12, confirmed by integrated-server logs. The helper
now initializes new audit directories with a valid value of 5. Native capture and
some input paths were unreliable; Minecraft F2 screenshots and a window-targeted
native click helper allowed testing to proceed. Pause-on-lost-focus was disabled
for the timed circuit checks. The isolated creative superflat world was saved,
and the client exited normally after approximately 34 minutes.

## Live outcomes

- The normal Aura encyclopedia item did not open in the tested use path. A vanilla
  written-book control did. The Aura item did receive generated book components.
- Copying those components to a vanilla written book, as a diagnostic only,
  demonstrated clipped content: page 1 showed two of six checklist entries.
  This does not count as a successful normal Aura-item workflow.
- The small node model had a full-block selection outline and an apparent missing
  stone face beneath it. Source confirms default full shapes/occlusion properties.
- The enchantable-item tag failed to load; applying the red Kaleidoscopic enchantment
  to a diamond pickaxe with `/enchant` was rejected. The custom enchanter machine
  and all effect combinations were not tested.
- In a seeded creative-pump circuit, adjacent upper nodes stalled: the upper node
  held 12456 red aura, while lower power and smelter progress stayed at zero at the
  checkpoint. A revised circuit with a one-block air gap produced an iron ingot
  within ten running-world seconds, without direct power injection. Its upper and
  lower nodes held 2145 and 11684 red aura; smelter power/progress was 29007 / 1.
  Node redstone emission plus redstone-gated sending is a plausible explanation
  for the adjacent-layout stall; the original's intended adjacency behavior still
  needs comparison. This does not establish survival-fueled progression parity.

The first datapack version used a slash instead of a colon in scheduled function
identifiers. The corrected, reloaded version produced the reported checkpoints;
the initial absent checkpoints were an audit setup error, not a mod defect.

Sol High is reserved for difficult implementation work after the audit identifies
specific defects. No production fixes or release publication are part of this baseline.

## Completion criteria

The guidebook must offer navigable categories/entries and useful links, display
every instruction without clipping, and support actual progression. World-facing
systems must make their state discoverable, function through player interactions,
and persist correctly. Tests that check text or file existence alone cannot prove
these requirements.

The remaining-work list distinguishes live-reproduced defects, source-confirmed
missing behavior, third-party reports and still-untested risks. This baseline is
not a full original-mod replay or a release sign-off.
