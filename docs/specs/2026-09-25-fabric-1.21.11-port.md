# Aura Cascade Reimagined: Fabric 1.21.11 Port

Date: 2026-09-25. Status: implementation authorized after specification review;
the target port is not yet validated. The user subsequently authorized committing
the corrected source, implementing the 1.21.11 branch, and publishing after its
acceptance checks pass. The original specification-only turn ran no builds/games.

## Decision And Scope

Proceed as a bounded forward port of the corrected 0.2.1 gameplay, contingent on
the dependency proof below. Do not restart from the original mod or use the old
1.21.11 prototype as the behavioral baseline. Retain 1.21.1 as canonical.

The initial port is moderate engineering work, not a version-number edit.
Most gameplay intent, assets, guide content and regression scenarios are reusable.
Minecraft-facing code and the QA harness need adaptation. Future ordinary content
and logic updates should be substantially cheaper than the initial migration.

Planning allowance: roughly 3-7 focused engineering days for baseline capture,
dependency proof, migration and bounded release validation, assuming dependencies
work. This is a low-confidence effort estimate, not an agent wall-clock promise.
Re-estimate after dependency resolution and the first target compile. A substantial
Patchouli fork repair is outside this allowance and requires a scope decision.

Non-goals: 26.x, other loaders, new mechanics, rebalance, an engine rewrite,
universal multi-version framework, exhaustive legacy parity or completing all
previously untested mechanics as an incidental part of this port.

  Mojang mappings, Loom 1.14.10, Gradle 9.4.1 and Fabric Loader 0.19.1.
- Product version is `0.2.1+1.21.1`; published artifact SHA-256 is
  `2290a1a344fa8e1e43d631729b5f88d422923d573db90d1a592945fecc1aacc8`.
- Current inventory: 138 main Java files, 12 configured mixins, 10 Java files
  containing entity/block-entity save/load overrides, and 161 item-definition
  JSON files. These are inspected surfaces, not predicted edit counts.
- Recorded baseline: 252 tests across 62 suites plus bounded gameplay checks.
  These results belong to 1.21.1 and do not pass the target-version gate.
- The checkout has extensive tracked and untracked changes; HEAD is the earlier
  source publication, not a committed snapshot of the released hotfix. A new
  worktree from HEAD alone would omit the corrected implementation.

Before implementation, inventory and preserve all local changes. Prepare a
reviewed, secret-scanned source checkpoint that identifies the actual 0.2.1
implementation. Do not stage the whole workspace, discard files, or accidentally
include later unrelated edits. Preserve the published JAR and its hash; a fresh
build's ZIP hash need not match unless reproducibility has been established.
Record the source revision and build provenance independently.

## Dependency Gate

Use Java 21 and official Mojang mappings on 1.21.11. Keep the existing remapping
Loom approach; do not apply 26.1's unobfuscated toolchain migration here.

| Component | Investigated candidate | Required proof |
| --- | --- | --- |
| Loader | Official metadata lists stable 0.19.5 | Pin a compatible release and verify client/server launch. |
| Fabric API | Maven lists 0.141.6+1.21.11 | Resolve exact target artifact; compile against its APIs. |
| Loom/Gradle | Existing 1.14.10/9.4.1 are starting candidates | Resolve and build on Java 21; change only if necessary. |
| Patchouli | Community `Patchouli: Fabric Edition`, 1.21.11-94.4-fabric, CurseForge project 1664943 | Verify binary identity, dependencies, API, license notices, book loading and distribution coordinates. |
| Energy API | Maven `teamreborn:energy:4.2.0` | Verify compile/runtime transaction and sided lookup behavior. |

The official Patchouli Maven metadata inspected today contains 1.21.1-93-FABRIC,
but no 1.21.11 release. The community fork advertises a 1.21.11 Fabric build and
its source branch `port/1.21.11-fabric` resolves to
`a96b648072f7dfad98acbb7c8379d7783741ac20`. This source observation does not establish
that the published binary was built from that commit. Keep it as an external
dependency, not silently copied into Aura's MIT source or bundled without review.
Verify the actual JAR mod ID, API and checksum before choosing its dependency
coordinate. Do not assume that changing the existing official Maven version works.

Energy 4.2.0 JAR metadata permits Minecraft >=1.21.5, Java >=21 and Fabric Transfer
API >=5.1.0. Broad metadata is not proof of 1.21.11 runtime compatibility. Energy
5.0.0's current upstream development properties target 26.1; do not select it
merely because its number is higher.

Gate result must be a working Aura book and energy API resolution on the target.
If Patchouli is unsuitable, stop and report alternatives and effort; do not
downgrade the encyclopedia to vanilla book pages or silently change loaders.

## Migration Work

| Area | Concrete source surface | Required result |
| --- | --- | --- |

| Persistence | `NbtCompat`, ten save/load override files, storage books, accessory state, wand and fairy data | Adapt optional NBT access and ValueInput/ValueOutput-era APIs while preserving data meaning and stable field names where possible. No silent empty inventories or lost receipts. |

| World/game hooks | Twelve entries in `aura.mixins.json` | Review target methods, descriptors, fields and call ordering against target sources; preserve damage, mining, loot, spawning, food, explosion and item-lifetime behavior. |
| Networking | Accessory and Bookshelf Coordinator payloads, menus, fairy synchronization | Correct server authority, validation, player ownership, disconnect/rejoin and target codecs. |
| Data/resources | Recipes, tags, enchantments, models and Patchouli resources | Target-format validation without silently changing recipes, outputs, effects, IDs or instructional content. |
| External energy | `AuraFluxEnergyBridge` | Preserve transaction rollback/commit and consumption rules; prove against a compatible receiver or explicitly block interoperability acceptance. |
| QA/release tooling | `scripts/qa`, observer/MP sources, `publish_beta.py`, publisher tests | Target-isolated launchers and manifests; no hardcoded 1.21.1 profile or wrong Patchouli dependency on a 1.21.11 upload. |

Do not disable failing mixins with `require=0`, remove tests, or stub mechanics
to get a green startup. A successfully applied mixin still needs an effect test.
Several logic classes use Minecraft types; package names do not imply a completely
engine-independent shared module. Reuse logic without forcing a premature split.

The version adapter must preserve all five 0.2.1 fixes: dropped-item crafting
effects, one-shot empty-network placement previews with fresh link geometry,
first-open Creative tab selection with later choice retention, truthful stable
Aura HUD rows, and nine distinct Encyclopedia landing links. Retain the immersive
amethyst-plus-eight-gold-nugget recipe producing two White Aura Crystals.

## Branch And Update Policy

Use the same repository with `main` remaining canonical 1.21.1 and a proposed
`fabric/1.21.11` branch derived from the reviewed corrected checkpoint. Do not
rename/create branches during this specification task. Keep similar paths and
class organization to make comparisons and cherry-picks useful.

1. Make behavioral changes on 1.21.1 first, with focused tests and one coherent
   change per commit. Keep formatting and platform-only edits out of those commits.
2. Classify each change: content, gameplay logic, platform API or persisted data.
3. Forward-port it to 1.21.11, normally with `git cherry-pick -x`; resolve actual
   API differences deliberately rather than merging an entire branch wholesale.
4. For target-only API corrections, record why no 1.21.1 counterpart is needed.
   Feed any discovered shared bug back into canonical first.
5. Track source commit, target commit, semantic version, disposition and validation
   in a small forward-port ledger. A resolved conflict is not a behavioral test.
6. Run the applicable tests on both branches and target packaged smoke before
   claiming the update is available on both versions.

Expected recurring effort, excluding unrelated feature development:

| Change | Typical difficulty after the initial port |
| --- | --- |
| Guide wording, textures, ordinary balance constants | Low; usually a focused patch plus resource/visual checks. |
| Recipe changes | Low to moderate; intent carries over, JSON schemas may differ. |
| Aura math, recipe matching, machine rules | Low to moderate; preserve shared test cases and adapt Minecraft call sites. |
| New machine/item with ordinary existing patterns | Moderate; registration, assets, data, guide and runtime validation on both. |
| HUD, fairy renderer, input, mining/combat/explosion hook | Moderate to high; port independently to target APIs and retest behavior. |
| Inventory/network/save format change | High attention; round-trip and ownership/migration checks on both versions. |

Updates are not automatic and will not use one universal JAR. Initially use
branch-based maintenance, not duplicated repositories or a new abstraction
framework. Reconsider shared-source/version tooling only if repeated real changes
demonstrate that selective forward-porting costs more than maintaining that tooling.

Proposed initial artifact: `aura-cascade-0.2.1+1.21.11.jar`. If canonical gameplay
changes before the baseline is frozen, explicitly rebase the target scope/version
or track later changes as pending; never label newer gameplay as unchanged 0.2.1.
Subsequent matching releases use the same gameplay version with different Minecraft
suffixes. Record target-only build corrections distinctly and never overwrite an
already published artifact with different bytes under an ambiguous version.

## Implementation Sequence

1. **Baseline/dependency proof:** reviewed source checkpoint, dependency identities,
   minimal target compile, actual Patchouli book proof. Re-estimate effort here.
2. **Server/common port:** registration, serialization, items, entities, API calls,
   networking and all mixins. Run regression and dedicated-server checks.
3. **Client port:** fairy/item rendering, menus, HUD, Creative inventory, full book
   and the five hotfix behaviors. No placeholder visual replacements.
4. **Target acceptance:** packaged artifact, live fixtures, persistence and
   two-client authority checks. Fix observed regressions; retain honest unknowns.
5. **Forward-port rehearsal/release:** replay one real canonical update with its
   test and ledger entry; review artifact/dependencies/version; prepare beta notes.

For implementation delegation, isolate ownership by subsystem and preserve the
previous Luna/Sol/independent-playtest division. Only one integration owner may
start a heavy build or game workload. No workers are launched for this spec.

## Acceptance And Evidence

- Account for every baseline regression scenario. Port tests whose API fixtures
  changed; do not treat matching test counts or removing source-text assertions
  as evidence. Document replacements and any known source-version coverage gaps.
- Exact target JAR loads in a clean Fabric client and dedicated server with no
  missing mixin targets, missing registry entries, broken resources or client-only
  class loading on the server. Record version, dependency list and artifact hash.
- All 41 guide entries and their content load. Re-run actual-font layout checks;
  pagination may change, so 371 pages is baseline evidence, not a mandatory target
  count. Click all nine landing links and sampled recipe/back/category links at
  GUI scales 2 and 3; verify amethyst recipe and no clipped text.
- Exercise each changed mixin: explosion terrain/ore controls; accepted/rejected
  damage and combo; mining/drop/final durability; Digger/enchantment composition;
  Glider fall behavior; Scarer natural-spawn hook; food completion/cancellation;
  transformed-item refresh/merge/reload; Red Hole repeated blasts and freeze control.
- Check actual colored sword appearance and fairy animation, not merely model JSON
  existence. Recheck all five hotfix behaviors, including mid-plan obstruction and
  newly added neighbors, truthful zero rows, and effects caused by real crafting.
- Run fueled progression through representative processor/vortex outputs, partial
  receipt reload, storage search/retrieval/item conservation, fairy binding/release,
  and two-client owner-only state with logout/rejoin cleanup.
- Add a real compatible external-energy receiver test for the target dependency;
  no fake receiver unit test may be presented as external-mod compatibility.
- Save/reload target-native fixtures covering aura, active machines, receipts,
  component-rich storage items and bound accessories/fairies. Separately attempt
  a copied 1.21.1 -> 1.21.11 fixture upgrade and report exact outcomes. Never open
  the user's original world for migration tests; never promise downgrade support.
- Old 0.1.x 1.21.11 world compatibility is a separate fixture/decision, not implied
  by unchanged IDs. Establish it before advertising that upgrade path; otherwise
  make the limitation prominent and recommend a new world or backed-up trial.
- Carry the current untested-mechanics list forward. Neither a new version nor
  inherited 1.21.1 evidence turns those gaps into passes.

Record ordinary input, seeded materials/power, screenshots, state assertions,
negative controls, exact candidate and failures separately. QA observer/bridge
code stays outside the product artifact. Prefer a compatible existing harness or
Fabric Client GameTest; do not assume the 1.21.1 private bridge binary works.

## Memory And Release Safety

Retain the user's 4.5 GB budget for Minecraft/build/test tooling, excluding Codex
and desktop apps. Start from the existing bounded heaps, one Gradle worker and
serialized workloads; measure target native/private overhead as well as heap.
Sampled limits are not hard OS caps. Coordinate with PsiAI before any game launch;
no clear window is assumed from old messages. End every owned QA process normally.

The current publisher hardcodes Minecraft 1.21.1 and the `patchouli` CurseForge
relation. A target release needs explicit version validation and the dependency
project actually selected by Gate 1, potentially `patchouli-fabric-edition`.
Keep project ID 1519395, beta labeling and original credits. Add wrong-version,
wrong-dependency and hash-mismatch publisher tests. Never upload the 1.21.1 JAR
under a 1.21.11 label. The subsequent user instruction authorizes publication
after successful validation without another confirmation. Use the requested
Tim Osterhus identity for future reviewed commits;
never commit credentials, local game state or private bridge tokens.
